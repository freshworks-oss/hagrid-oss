# Version [3.7.0] - [COMPLETED]

## Added
### Support for file-based database H2  

We have added a support for another infra layer using an H2 database which can be used as a replacement of mongo db. 
In most of the cases, developers should use H2 layer instead of Mongodb. There are multiple benefits of using H2 infra instead of 
`mongo`

1. H2 works independently on disk file and scales as the number of syncs or pods increases
2. No separate infra is required.
3. As each pod / server will have its own H2 database file, there are no connection management issues
4. As H2 is implemented in embedded mode instead of TCP with in Hagrid, latency is minimum. 
5. Overall, using H2 has given us 3X performance improvements. Earlier for 10M beans with Mongo as infra layer was taking approximately 
   1.5 Hrs to complete, now for 10M beans it takes 20 minutes. 


Here is what changes need to be done in `hagrid.yml`

```java
infra_type: "h2"
h2_data_path: "/Users/aaggarwal/Documents/hagrid-releases/data/hagrid-3.7.0/hagrid-db-file"
h2_database_type: "file"
        
```

`infra_type` for mongo is `persistent` and for H2 it is `h2`
`h2_data_path` defines in which directory do you want H2 to create the database file
`h2_database_type` defines which kind of H2 database you like to goahead, "file" for large data set and "inmemory" for smaller
data set. 

### Support for MDC variables in logs
Now `Hagrid` passes all MDC variables from main thread to its `traverser` and `processor` threads.
